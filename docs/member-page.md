# メンバー個人ページ

システムメニューの「メンバー個人ページ」を開き、研究会名簿から自分の名前を選びます。既存のログイン方法を使い、個別のログインアカウントや名簿との紐付け設定は追加しません。名前はブラウザごとに記憶します。現在の運営用のアクセス範囲内で名前を切り替えて利用する画面です。

## 出欠と役割

開催日ごとの出欠を変更すると、イベントの出欠登録にも反映されます。演者が欠席・午前のみ・午後のみを選ぶ場合は確認を表示します。欠席と当日役割が重なる場合は、運営へ担当変更を相談するアラートを表示します。役割は個人ページから変更せず、イベントの運営画面で割り当てます。

## 役割に連動するタスク

イベントの「タスク・期限管理」で、各タスクの「役割と連動するタスクに設定」を開き、役割を選んで「連動設定を保存」を押します。当日役割は開催日も指定できます。「担当するすべての開催日」は、その役割をどれかの開催日で担当するメンバーが対象です。準備役割はイベント全体に連動します。

役割が割り当てられているメンバーの個人ページに該当タスクを表示します。担当変更は次回の読み込みに反映されます。複数の担当者は同じタスクを共有し、個人ページでは進捗のみ変更できます。既存のログインアカウントに対する主担当・協力者の設定は別の設定として維持します。

期限超過、7日以内の期限、今後の出欠未確定、演者の出欠矛盾を画面上に表示します。過去のイベントは、未完了の担当タスクがある場合に表示します。「過去のイベントも表示」で全件を確認できます。アラートは画面表示です。

競合した更新は保存せず、最新情報の取得を案内します。出欠・タスク進捗・連動設定には更新履歴を残します。

## 開発時の確認

`node --test tests/member-page.test.mjs` で、開催日別の役割連動、共有タスクの進捗、更新競合、演者の出欠確認、期限アラート、履歴失敗時のロールバックを検証します。

`npm run build` の後に `node scripts/check-member-page.mjs` を実行すると、隔離した一時DBと架空データで1280px・390px・320pxの画面操作を確認します。結果とスクリーンショットは `test-results/browser/member-page-*` に保存します。
