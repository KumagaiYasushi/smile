# イベントの基本タスクと任意タスク

2026-11-03の利用者回答に基づき、イベント登録後に基本タスクを自動設定する。ベーシックコース・講演会・セミナー・その他で共通。単回・複数回・日程未定でも登録でき、複数回コースは親イベントに一組を作成する。

外部講師「あり」では次の3件、「なし」では最後の参加者確認メール1件を作成する。

1. 外部講師への依頼状
2. 外部講師への資料一括依頼（略歴・プロフィール写真・抄録300字・抄録800字）
3. 参加者への確認メール

外部講師が未設定の場合は1件から開始する。従来の外部講師氏名・区分だけが保存されたイベントは外部講師ありとして扱う。後から外部講師ありに変更すると不足する2件を追加する。なしへ変更しても既存タスクは消さない。
初期状態は「未着手」、期限は未設定、担当者は未割当。イベント詳細の「タスク・期限管理」で期限・担当者・説明・状態を変更でき、「＋ タスクを追加」から任意のタスクを追加する。
タスクの自動登録ではメールを送らない。各タスクに文面確認・コピーを備え、Gmail連携後に利用者が文面を確認して送信できる。[文面・Gmail連携](gmail-tasks.md) を参照。

## 既存イベントと重複防止

既存イベントでは、次のイベント保存時、または「タスク・期限管理」を初めて開いた際に、不足する基本タスクを初期設定する。同名のタスクが既にあればそれを利用し、説明・進捗・期限・担当者を上書きしない。
初期設定済みのタスクはイベントの再保存・一覧の再取得でも重複しない。改名・完了・削除後もその記録を保持し、削除したものを自動復活させない。再び必要なら任意タスクとして追加する。

以前の資料4タスクは、未編集・未着手・期限や担当が未設定で保存済みメール文面もない自動作成分だけを、一括依頼にまとめる。削除操作の履歴と初期設定済みの印は残す。編集済み・着手済み・保存文面のある記録はIDと内容を保持する。以前の資料4件がすべて完了なら、新しい一括依頼も完了として作成し、未着手へ戻さない。

テンプレートからの生成は引き続き停止する。テンプレート編集による基本タスクの変更や、テンプレート期限の自動適用は行わない。[タスクテンプレート](task-templates.md) を参照。

## 保存と検証

`event_standard_tasks` はイベントとタスク種別の組を一意に保持する。タスク削除時はタスクIDだけを空にして初期設定済みの印を残し、イベント削除時は関連する印も削除する。
イベント作成・編集と基本タスク作成は、出欠・昼食・打ち合わせを含め同一トランザクションで保存する。失敗時は全体を取り消す。操作アカウントはログイン中の有効メンバーから確定する。
POST `/api/seminars/{id}/tasks/initialize` は既存イベントの不足分を設定し、`created` 件数を返す。認証と同一Originを確認し、タスクGETでは書き込まない。
単体・API結合テストで3件／1件、全4種別、後からの追加、同名の既存作業、改名・完了・削除の保持、重複防止、任意追加、認証・CSRF、監査失敗や登録失敗の全体取り消しを確認する。
