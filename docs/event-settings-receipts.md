# 開催回数・任意の時刻・入金確認後の領収書

2026-11-02の追加要望に基づく変更。ベーシックコース・講演会・セミナーの全種別で共通。

## イベント設定

- 新規登録と編集で、開催回数を「単回」「複数回」から必ず選ぶ。初期選択はしない。
- 単回は開催日を最大1日、複数回は複数日を登録できる。日程未定のままでも回数は選択する。複数回は最初の1日だけ決まった段階でも保存できる。
- 既存イベントの回数は推測せず「未設定」で保持する。編集時に選択する。日程変更の前にもイベント編集で選択する。
- 開催日は年月日のみが初期状態。各日付の「時刻を設定」をオンにした日だけ、開始時刻と任意の終了時刻を日本時間で登録する。
- 一覧・詳細・SNS文案・メール文案では、設定した日だけ時刻を表示する。時刻設定を解除すると年月日のみへ戻る。
- 日程変更後、新しい日付には時刻を自動転記しない。変更後にイベント編集から設定する。旧日付の時刻は保持し、同じ日付へ戻したときに再表示する。
- 講師の基本情報では「外来講師」「研究会講師」を選択できる。「講師・サポートの出欠予定」では、この2区分と「研究会サポートメンバー」を複数人登録できる。
- 昼食は全種別で新規登録時と登録後の両方で入力できる。入力は任意。

## 主な参加対象

歯科衛生士・歯科医師・その他を複数選択のチェックボックスで登録する。新規イベントは3つとも選択済みで、少なくとも1つ選択する。詳細・SNS・メールに選択した対象名を表示する。
既存の自由記載の参加対象は読み取り・移行で書き換えない。既知の職種名だけなら対応する選択肢として表示し、任意の自由記載は選択変更まで以前の記録として保持する。
`seminars.audience_roles` に選択職種をJSON保存し、表示用の `target_participants` と同期する。既存行の追加列はnull、既存の文字列・更新日時は保持する。従来クライアントが自由記載だけを更新した場合は、その記載を優先して選択職種をnullへ戻す。

## 入金確認と領収書の操作

1. イベントの「参加者名簿」で参加者を登録し、支払方法を「銀行振込」にする。
2. 「未入金」ボタンで編集画面を開き、実際に確認した入金額を入力して保存する。参加費を初期表示するが、確認した額に変更できる。
3. 「領収書を発行」を選び、確認画面で金額を確認して発行する。
4. 表示された「領収書」リンクから開き、「印刷 / PDF保存」を使う。

編集画面で入金状況を「入金済」にして金額を入力・保存する方法もある。現金・その他・支払方法未設定の参加者にも入金額を記録できるが、この振込向け領収書発行の対象にはしない。
既存の「入金済」フラグだけでは確認したとみなさず、確認日時・金額は空のまま残す。「入金確認待ち」から改めて確認・保存する。
入金合計は参加費からの推測額ではなく、登録された入金額を合算する。旧データの未確認金額は含めない。

発行時点の宛名・職種・イベント名・開催日・会場・講師名・入金額・発行日（日本時間）・操作アカウントを保存する。参加費や氏名を後で変更しても発行済み領収書の内容は変わらない。
領収書No.は発行前に指定できる。未指定は `SMILE-{イベントID}-{参加者ID}` を使用し、他の発行済み領収書と重複した番号を拒否する。再試行で同じ領収書を重複発行しない。
発行済みの入金状態・支払方法・入金額・領収書番号は変更を拒否する。取消・訂正発行・返金は今回の対象外。参加者・イベントの明示的な削除は従来同様関連データも削除するため、検証用データで試す。
メール送信や金融機関との照合は行わない。

## 保存とAPI

- `seminars.occurrence_type`、`event_times`、`lecturer_role` を追加。既存ID・日程・更新日時を保持する。
- スタッフの旧2区分は勝手に分類し直さず表示・回答を保持。編集時に新しい3区分から選ぶ。移行ではID・バージョン・日時・履歴・採番の進みも保持する。
- `participants` に支払方法・入金額・確認日時・確認アカウントを追加する。
- `participant_payment_history` に入金項目の変更前後・操作アカウント・日時を保存。参加者氏名などの自由記述は履歴へ複製しない。
- `participant_receipts` に発行内容を保存。入金保存と履歴、発行と番号更新はそれぞれ同一トランザクションで行い、途中失敗時は全体を戻す。
- イベント単位の従来の「領収書発行済み」チェックは保存値を保持し、画面チェックリストから外す。発行判定には参加者別の領収書を使う。
- GET `/api/seminars/{id}/participants/{pid}/receipt` は発行済みの内容のみ返す。未発行は404。
- POST 同パスで銀行振込・入金確認・金額・ログイン状態を確認して発行する。不適格は409、別イベントの参加者は404。
- 参加者APIと領収書APIはログイン済み運営メンバー向け。書き込みは同一Originを要求し、応答はキャッシュしない。確認日時・操作アカウントの直接指定を拒否する。

## 検証

`npm test` は回数の必須選択・実在日付・時刻・移行・再起動・旧日程保持・確認済み振込だけの発行・金額固定・再試行・改ざん拒否・履歴失敗のロールバックを確認する。
`npm run test:smoke` は全3イベント種別で、昼食を後から追加できること、回数・時刻、入金確認と領収書、認証・イベント境界・CSRFを確認する。
`npm run test:browser` は3画面幅で回数の必須選択、時刻の設定・解除、3区分の選択肢、入金額入力、領収書発行・再表示・1ページのPDFを確認する。
