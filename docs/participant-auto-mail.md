# 申込受付・入金確認の自動メール

参加者名簿の「申込受付・入金確認の自動メール」から設定する。既定は停止中。Googleフォームの取込、手動の参加者追加、入金確認の登録に連動する。実送信はGmail接続とイベント設定を有効にした後に行う。開発テストは架空の申込と模擬Gmailのみで実施する。

## イベントの設定

1. 送信に使う運営アカウントでログインし、システムメニューの「Gmail連携」でGoogleに接続する。既存のGmail API・OAuth設定を使用する（`docs/gmail-tasks.md` の設定手順）。
2. 対象イベントの「参加者名簿」→「自動メール・Googleフォーム連携の設定」を開く。
3. 「共通の振込先2口座を登録・変更」で口座名と、金融機関・支店・種別・番号・名義を登録する。2口座は研究会全体で共通。イベントごとに使う振込先を1つ選択する。
4. 臨床相談フォームのHTTPS URLは任意。空欄なら案内自体を省略する。イベントごとに別のURLを設定できる。
5. ベーシックコースだけに事前課題の入力欄を表示する。空欄なら課題の案内を省略する。他の種別では課題を含めない。
6. 職種を切り替えてメールのプレビューを確認し、「このイベントの自動送信を有効にする」を選んで保存する。設定を変更できるのは送信元の運営アカウント。ほかの運営メンバーの参加者追加・入金確認も、その設定済みGmailから自動送信する。

申込受付メールにはお礼、イベント名・日程、職種別参加費、選択口座、任意の臨床相談フォームとベーシックの課題を含める。入金確認メールには入金額と領収書PDFを含める。

設定を有効にしただけで、既存の参加者へ過去の受付メールを一斉送信しない。設定後の新規申込と新たな入金確認が対象となる。メール本文は申込・入金の処理で作成して記録し、送信開始後は宛先・文面を変更しない。

## Googleフォームとの接続（初回）

1. 申込用Googleフォームに次の項目を用意する。
   - 氏名（必須）
   - メールアドレス（必須。Googleフォームのメール収集機能も利用可能）
   - 職種（「歯科衛生士」「歯科医師」、それ以外は「その他」扱い）
   - 電話番号（任意）
   - 領収書宛名（任意。未入力なら氏名を使用）
2. アプリで設定を保存し、「フォーム連携用スクリプトを作成」→「スクリプトをコピー」を押す。
3. 申込用Googleフォームのメニューからスクリプトエディタを開き、生成したコードを貼り付ける。先頭の `SMILE.fields` の項目名を、フォームの質問名と完全に一致させる。
4. `setupSmile` を1度実行し、Googleが表示する権限を許可する。フォーム送信時と5分ごとの再処理トリガーを設定する。
5. 自分の確認用アドレスでフォームを送信し、名簿への登録・受付メール・振込先・領収書宛名を確認してから案内する。

生成コードにイベント専用の連携キーを含む。Googleフォーム管理者だけで扱い、チャットや公開ページには載せない。再生成は古いキーを無効にするため、Google側のコードも更新する。`APP_ORIGIN` に外部から到達できる公開HTTPS Originが必要。アプリのログイン画面へフォーム利用者を案内する必要はない。メール送信・実行時間等はGoogle側の利用上限に従う。

Googleフォームの回答IDとフォームIDで取込を重複排除する。同じ回答を再処理しても参加者や受付メールは増えない。フォーム回答の再送は最初に受け付けた登録を上書きしない。登録後の修正はアプリの参加者名簿で行う。削除した参加者を同じ回答の再送で復元しない。

通信エラー時はGoogleスクリプト側に未取込の回答を保持し、5分ごとに再処理する。連携前に質問名を合わせる。入力に不備がある場合はアプリ・Googleスクリプトの実行結果を確認し、修正する。

## 入金確認・領収書

未入金ボタンから実際の入金額・支払方法を確認して保存する。銀行振込の入金確認済み参加者は、同じ保存処理でメール送信待ちに登録され、領収書PDFを添付する。Googleフォームからの申込は未入金・銀行振込として取り込む。フォームから入金済み情報を指定することはできない。

領収書宛名は `receipt_name` として氏名とは別に保存し、発行時の宛名・金額・イベント情報・発行日・番号を固定する。宛名の末尾が「様」「御中」の場合は敬称を重ねない。発行済みの領収書宛名・入金情報・番号は変更不可。既存の手動発行・印刷も利用できる。領収書がすでに発行されている場合は同じ領収書を添付し、再発行しない。

## 送信状況と再処理

- 最新100件を「メール送信状況」に表示する。
- 参加者追加・入金確認のAPIで送信待ちを作成して処理する。画面表示中は1分ごと、Googleスクリプトからは5分ごとに未送信と結果不明を処理する。
- 参加者と種類（申込受付／入金確認）ごとに1件だけ登録し、送信開始をDBで確保して並行処理の重複を防ぐ。参加者・入金更新と送信待ち登録は同一トランザクション。
- 送信前の設定不備・明確な送信拒否は未送信として再処理できる。宛先不備は参加者名簿でメールアドレスを修正する。
- タイムアウトなど受け付けられた可能性がある場合は「送信結果の確認待ち」にし、自動再送しない。Message-IDと送信時のGmailアカウントで送信済みを照合する。確認できない場合はGmail側の送信済みも確認する。
- Gmailを別アカウントに切り替えても、過去の不明な送信を別のアカウントで照合・再送しない。
- 銀行振込を未入金へ戻した場合、まだ送っていない入金確認メールは対象外にする。領収書発行後は従来どおり入金情報の取消不可。

設定・送信待ち・取込ID・領収書をSQLiteへ保存する。実データの運用には永続保存とバックアップがある環境を使用する。

## API

- `GET/PATCH /api/seminars/:id/participant-mail`：設定・送信状況、版付き設定更新。ログイン・同一Origin確認が必要。口座の同時更新も別の版で保護する。
- `POST /api/seminars/:id/participant-mail`：`{action:"script"}` で連携キーを更新しコードを作成、`{action:"dispatch"}` で未送信処理・送信照合。
- `POST /api/forms/:id`：専用Bearerキーでフォーム回答取込、または `{action:"dispatch"}` で対象イベントだけ再処理。受付可能項目は回答ID・氏名・職種・メール・電話・領収書宛名だけ。入金情報は受け付けない。本文上限16KiB。
- `GET /api/seminars/:id/participants/:pid/receipt/pdf`：発行済み領収書PDFを取得。ログインとイベント・参加者の組合せ確認が必要。

Gmailの資格情報は既存の暗号化接続を使う。連携キーはハッシュだけを保存し、設定GETでは返さない。PDFを公開URL化せず、メール添付として送る。テストでは模擬GmailのMIMEと実際のPDFから宛名を確認し、実アカウントへの送信は行わない。
