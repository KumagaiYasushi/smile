# 講師・サポートメンバーの出欠予定

2026-11-02の利用者指定に基づき、ベーシックコース・講演会・セミナーに共通の事前出欠登録を追加した。

名簿のラジオボタンでイベント・開催日ごとの出欠を登録する操作と配色は [名簿による出欠登録](staff-roster.md) を参照。

## 操作

1. イベント詳細の「講師・サポートの出欠予定」を開く。
2. 「登録済みの講師・スタッフ名を取り込む」でイベント基本情報の講師名・サポートメンバー名を取り込む。初期値は各日とも未回答。
3. 「＋ メンバーを追加」で追加することもできる。外部講師など、ログイン用アカウントを持たない人も氏名で登録できる。
4. 各人の「編集」で氏名、役割（外部講師／研究会講師／研究会サポートメンバー）、各開催日の予定を登録する。

予定の選択肢は「未回答」「出席予定」「欠席予定」「調整中」。日程未定のイベントは「日程未定」として予定を登録できる。
役割で絞り込み、日別の人数集計、直近100件の変更履歴も確認できる。
出欠予定は参加者名簿の実出席、受講履歴、タスク担当を変更しない。

旧区分が未設定の講師は自動で外来・研究会に分類しない。既存の回答を保持し、編集時に新しい3区分から選ぶ。基本情報で区分を選んだ講師は、その区分で取り込む。

## データの扱い

- `event_staff` にイベント・氏名・役割・日付ごとの予定・バージョンを保存。同一イベントで氏名と役割が一致する登録は重複させない。
- 複数人の講師を追加できる。取り込み元の講師名欄は1つの氏名として扱い、自動で文字列を分割しない。
- 取り込みを再実行しても、同じ氏名・役割の出欠予定を上書きしない。基本情報の氏名変更も登録済み予定へ自動で連動させない。必要に応じて編集・追加・削除する。
- 現在の開催日だけを編集する。旧日程の回答は保持し「旧日程の登録内容」で確認できる。新しい日付に旧回答をコピーしない。
- 日程未定から日程確定に変わった場合も、確定日について改めて登録する。同じ日付に戻した場合はその日付の既存回答を表示する。
- サーバーは保存直前に開催日と個人レコードのバージョンを確認する。他の操作で変更されていれば409とし、上書きしない。
- 保存失敗・競合時は入力を保持する。競合時は必要な入力を控えてキャンセルし「最新情報を取得」してから編集し直す。
- `event_staff_history` に操作アカウント、対象ID、変更前後の役割・予定、操作日時を記録する。履歴には氏名を複製しない。
- 保存・削除・一括取り込みと履歴の記録は同じトランザクション。履歴の記録に失敗した場合も全体を戻す。
- イベント削除時は当該イベントの予定と履歴も削除する。

## API

すべてログイン済み運営メンバー向け。書き込みは同一Originを必須とし、返却値をキャッシュしない。

| メソッド・パス（`/api/seminars/{id}` 以下） | 用途 |
| --- | --- |
| GET `/staff-attendance` | イベント名、開催日、全員の予定、変更履歴 |
| POST `/staff-attendance` | 氏名・役割・各日予定の追加 |
| PATCH `/staff-attendance/{sid}` | 予定・氏名・役割の変更 |
| DELETE `/staff-attendance/{sid}` | バージョン確認付き削除 |
| POST `/staff-attendance/import` | 基本情報から未登録の氏名を取り込む |

追加・更新には `name`、`role`（`EXTERNAL_LECTURER` / `SOCIETY_LECTURER` / `SOCIETY_SUPPORT`）、`schedule`（取得した日付配列）、`responses`（日付をキーとする予定の辞書）を送る。
予定値は `UNANSWERED` / `ATTENDING` / `ABSENT` / `TENTATIVE`。日程未定時は空文字列キーを使う。
更新には `version`、削除には `version` のみ、取り込みには `schedule` のみを送る。
別イベントのID、不正な入力、未知の予定、現在の開催日以外の回答を拒否する。

## 検証

`npm test` で日別の保存、予定変更、取り込みの冪等性、旧日程保持、未定から確定への変更、競合、イベント境界、監査失敗の全体ロールバック、削除の連鎖を確認する。
`npm run test:smoke` で全3種別、認証、CSRF、保存・編集・削除、日程変更との結合を確認する。
`npm run test:browser` でPC・スマートフォン幅から取り込み・登録・編集・入力保持・競合・絞り込み・履歴・日程変更後の確認・削除失敗からの再試行を操作する。

本人への出欠依頼メール送信、回答用の外部公開フォーム、開催回IDでの管理は未実装。今回は日付単位の事前予定を運営メンバーが登録する。

午前のみ（`AM_ONLY`）・午後のみ（`PM_ONLY`）も開催日別に登録できる。研究会の名簿ラジオでは両方とも緑色で表示する。昼食の初期人数は両方を出席として各1名数え、必要に応じてオーダー個数を変更する。
