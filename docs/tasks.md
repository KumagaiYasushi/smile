# イベント別のタスク・期限管理

## 使い方

1. ログイン後、イベント詳細の「タスク・期限管理」を開く。
2. 自動設定された基本タスクを確認し、期限・担当者などを編集する。任意の作業は「タスクを追加」から名称、説明、期限、状態、重要設定、主担当者、協力者を登録する。
3. カードの状態欄で「未着手／進行中／確認待ち／完了」を変更できる。
4. 状態別のほか、重要タスク・期限超過・主担当未割当で絞り込める。
5. 「変更履歴」で期限・状態・重要設定・担当の変更を確認する。
6. 別のメンバーの更新と競合した場合、上書きせず409を返す。
   入力を残してエラーを表示するので、内容を控えたうえで「最新の内容を取得」から読み直す。

名称は1〜200文字、説明は2000文字以内。期限は日付単位で、日本時間の当日より前、かつ未完了のタスクを期限超過とする。
主担当者は最大1名で、割り当て前は未割当。協力者は複数指定できる。
無効化されたアカウントを新たに割り当てることはできない。既存の割り当ては保持し、画面で利用停止と表示する。

## 実装と互換性

- `event_tasks`・`task_collaborators`・`task_history` を追加する。既存のイベント、参加者、5項目のチェックリストは変更しない。
- 全運営メンバーが登録・閲覧・編集できる。未認証は401、外部Originからの書き込みは403。
- URLのイベントIDとタスクの所属を照合し、別イベントのURLでの操作は404。
- タスクと協力者の保存・監査記録は同じトランザクション。監査保存失敗時は業務変更も取り消す。
- 更新・削除には取得済みの `version` を要求し、同時編集による変更消失を防ぐ。
- 変更履歴は操作アカウントID、時刻、変更項目、期限・状態・担当ID・重要設定の前後を保持する。
  自由記述の名称・説明は履歴へ複製しない。削除後も監査記録はDBに残すが、削除済みタスクの履歴画面は未実装。
- イベント削除時は所属タスクと協力者の関連を削除し、監査記録は保持する。
- タスク保存は外部サービスの通知・送信・カレンダー更新を行わない。

## API

| メソッド | URL | 内容 |
| --- | --- | --- |
| GET | `/api/members` | 割り当て候補の有効アカウントIDとメールのみ |
| GET / POST | `/api/seminars/{id}/tasks` | イベントのタスク一覧／作成 |
| GET | `/api/seminars/{id}/tasks/{tid}` | タスクと変更履歴 |
| PATCH | `/api/seminars/{id}/tasks/{tid}` | `version` と変更項目による部分更新 |
| DELETE | `/api/seminars/{id}/tasks/{tid}` | JSONの `version` を確認して削除 |

入力は `title`, `description`, `due_date`（YYYY-MM-DDまたはnull）, `status`, `important`,
`assignee_id`（アカウントIDまたはnull）, `collaborator_ids`（ID配列）。
状態値は `NOT_STARTED`, `IN_PROGRESS`, `IN_REVIEW`, `DONE`。作成時の必須項目は `title`。
タスクID・イベントID・操作担当者IDなど、利用者が書き換えられない項目は入力として受け付けない。

## 今回の範囲と残作業

2026-11-03から、外来講師ありでは6件、なしでは参加者確認メールの1件を自動設定する。初期期限・担当者は未設定で、任意のタスクも追加できる。既存イベントでの設定と重複防止は [基本タスク](standard-tasks.md) を参照。
テンプレートからの逆算生成は引き続き停止中。保存済みテンプレートは編集でき、過去に生成したタスクと期限は保持する。[task-templates.md](task-templates.md) を参照。
開催日変更時の期限は [差分プレビュー](reschedule.md) で全タスクの扱いを選んで変更できる。
手動登録タスクは相対日数を推測せず、保持または個別指定を選択する。
完了済み・固定日・個別変更済みの恒久ルール（U11）は確定せず、今回の変更ごとに明示的に判断する。
ベーシック各回の出欠・宿題粒度、全イベントを横断したダッシュボード、通知・外部カレンダー連携も別途必要。
仕様書AT01・AT02相当の機能は架空データで検証。実際の標準タスクと延期時ルールの業務受入は未完了。

## 検証

- `npm test`：入力エラー、イベント間の分離、状態遷移、同時編集、監査失敗時のロールバック、関連削除、日本時間の期限超過を検証。
- `npm run build`：ビルドと型検査。
- `npm run test:smoke`：ビルド後に実行。独立したローカルサーバーと一時DBで、認証・API・既存機能をまとめて検証する。
- `npm run lint`：既存メール画面のHook依存配列警告1件は継続。
- ChromiumのPC・スマートフォン幅で追加・編集・状態更新・絞り込み・履歴・削除と競合時の入力保持を確認済み。実機・他ブラウザーは未確認。[確認結果](ui-validation.md)を参照。
