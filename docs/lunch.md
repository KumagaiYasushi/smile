# 昼食の手配

2026-11-02の利用者指定に基づき、ベーシックコース・講演会・セミナーで昼食の対象・人数・費用・お店を管理できるようにした。

全イベントで新規登録時と登録後の両方で入力できる。昼食入力は任意で、イベントだけを先に保存することもできる。登録画面への追加は [イベント登録時の出欠・昼食](event-registration-extras.md) を参照。

## 使い方

イベント詳細の「昼食の手配」から「＋ 昼食の手配を追加」を選び、開催日と対象ごとに登録する。
同じ日でも複数の対象・店舗・メニューを別の手配として追加できる。

| 項目 | 内容 |
| --- | --- |
| 日程 | 現在の開催日から選択。未定も可 |
| 対象 | 講師／外来講師／サポートメンバー／参加者／その他 |
| 対象の詳細 | 氏名や提供対象の範囲など、1000文字以内 |
| 人数・食数 | 0以上の整数。空欄は未定 |
| 1食あたりの費用 | 円単位の整数。空欄は未定、0は無料 |
| 追加費用 | 送料等の円額。初期値0。空欄は未定 |
| 店舗情報 | お店・注文先、連絡先・住所、メニュー |
| 手配状態 | 未定／手配予定／注文済み／中止 |
| 備考 | 2000文字以内 |

合計費用は「人数（食数）×1食あたりの費用＋追加費用」で計算する。
計算に必要な項目が未定の場合は合計も未定。負数・小数・安全に表現できない整数や合計は拒否する。
同じ注文を対象別に分けて登録する場合は、送料などを重複計上しないよう該当する手配に一度だけ入力する。

対象の絞り込み、日程別の食数・費用集計、直近100件の変更履歴を確認できる。
集計は表示している対象の中止以外の手配を合算し、人数・費用が未定の件数を併記する。
複数日に同じ人へ昼食を用意する場合も、各日の食数として管理する。人数は手入力であり、講師・サポートの出欠予定や参加者名簿から推測・自動反映しない。

## 日程変更・失敗時の動作

イベント日程を変更しても、昼食の手配日・人数・店舗を自動で変更しない。
現在の開催日に含まれない注文は「旧日程」と表示し、中止以外の手配が残る場合は確認を促す。
店舗への連絡を済ませてから、編集で新日程への変更や中止を登録する。旧日程のまま店舗等の記録を修正することもできる。
日程未定から確定した場合は、未定の手配を編集して開催日を選択する。

保存直前に開催日とレコードのバージョンを確認する。他の操作で変更されていれば409として上書きしない。
失敗時は入力と表示を保持する。競合時は入力を控えてキャンセルし、最新情報を取得して編集し直す。
この画面は管理用の記録。店舗への実際の注文・変更・キャンセル送信は行わない。

## APIと保存

`event_lunch_plans` と `event_lunch_history` を追加する。既存イベントは空の手配一覧で始め、既存のID・日程・参加者を変更しない。

| メソッド・パス（`/api/seminars/{id}` 以下） | 用途 |
| --- | --- |
| GET `/lunch` | イベント名、現在の開催日、手配一覧、変更履歴 |
| POST `/lunch` | 手配追加 |
| PATCH `/lunch/{lid}` | 手配編集 |
| DELETE `/lunch/{lid}` | バージョン確認付き削除 |

追加・編集には `date`、`target`、`target_details`、`quantity`、`unit_price`、`additional_cost`、`shop_name`、`shop_contact`、`menu`、`status`、`notes` と、GETで取得した現在の `schedule` を送る。
編集は上記入力全体と `version`、削除は `version` のみを送る。対象値は `LECTURER` / `EXTERNAL_LECTURER`（外来講師）/ `SUPPORT` / `PARTICIPANT` / `OTHER`、状態値は `UNDECIDED` / `PLANNED` / `ORDERED` / `CANCELLED`。
日付・人数・金額の未定はnull。対象は必須、任意項目の省略は初期値となるため、編集時は保持したい項目も送る。
別イベントの手配ID、未知の項目・対象・状態、不正な日付・数値を拒否する。
ログイン済み運営メンバーのみ利用でき、書き込みは同一Originを必須とし、返却値をキャッシュしない。

手配と履歴は同一トランザクションで保存する。履歴保存に失敗した場合は全体を戻す。
履歴には操作アカウント、対象ID、日時、日付・対象区分・人数・費用・状態の変更前後を記録し、氏名・店舗連絡先・備考を複製しない。
イベント削除でそのイベントの昼食手配と履歴も削除する。

## 検証

`npm test`：費用・集計の精度、未定と0の区別、全対象、複数日・複数店舗、入力検証、競合、旧日程保持、監査失敗時のロールバック、削除の連鎖。
`npm run test:smoke`：全3イベント種別・全5対象、APIの作成・編集・削除、CSRF・認証、イベント境界、日程変更との結合。
`npm run test:browser`：PC・スマートフォン幅で登録・編集・集計・絞り込み・履歴・入力保持・競合・旧日程確認・保存削除失敗からの再試行。
