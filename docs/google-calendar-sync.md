# Googleカレンダーへの自動登録

イベント・確定した打ち合わせ・「開催する」懇親会を、HOME・ダッシュボードに表示している研究会カレンダーへ反映する。候補日時は、決定するまで登録しない。アプリ内での開発テストは架空データ・模擬Google APIだけを使い、実カレンダーは変更しない。

## 初回設定

1. システムメニューの「Googleカレンダー連携」を開く。接続・解除は管理者のみ、同期状況の閲覧・再同期は運営メンバーが利用できる。
2. Gmailと同じGoogle CloudプロジェクトでGoogle Calendar APIを有効にし、同意画面に `https://www.googleapis.com/auth/calendar.events` を追加する。
3. OAuthクライアントの承認済みリダイレクトURIに `https://公開ドメイン/api/calendar/callback` を追加する。Gmailのcallbackを置き換えない。
4. サーバーに `APP_ORIGIN`（HTTPS）、`AUTH_MFA_KEY`、`GMAIL_CLIENT_ID`、`GMAIL_CLIENT_SECRET` を設定する。Gmailの接続とは別にカレンダーへの許可を取得する。
5. 管理者としてログインし、「Googleカレンダーを接続」を押す。研究会カレンダーの「予定の変更」権限を持つGoogleアカウントで許可する。対象IDは既存 `STUDY_CALENDAR_ID` と共通。個人のメインカレンダーには登録しない。
6. 接続後は既存の予定も同期する。多数ある場合は未同期が残るので「未同期の予定を再同期」を押す。1回の手動・定期同期は10件まで。保存後・接続後の自動反映は最大30バッチを処理する。Google Calendar APIが有効で共有編集権限があることを、架空イベントで実運用前に確認する。

OAuthの状態照合・PKCE・有効期限・ワンタイム処理を行い、トークンはAES-GCMで暗号化して保存する。登録先は研究会の共有カレンダー1つ。接続管理者が利用停止になった場合は反映を停止する。他の運営メンバーの保存も、設定した共通接続から反映する。

## 反映内容

- イベント：各開催日を1予定として登録する。複数回は「第○回」を付ける。
- 打ち合わせ：確定日と開始・終了時刻、名称、オンライン等の開催方法。
- 懇親会：開催する区分に含まれる各会を登録する。開催しない・日程削除ではアプリから同期した予定を削除する。
- 時刻なしの日付だけの予定は終日扱い。終了日はGoogleの仕様で翌日を指定する。終了時刻なし・開始と終了が同じ場合は開始から1時間とし、日本時間で登録する。
- 名称・日程・時間・場所の編集に追従する。イベント・会議削除でも同期予定を削除する。共有カレンダーに手動で登録された別の予定には触れない。
- 送信内容は名称、日時、会場、アプリへのリンク。個人の出欠・申込者名・口座・支払い額・内部メモは含めない。参加者の招待リストを設定せず、招待メールを送らない。

## 保存・再試行

イベントおよび打ち合わせのDB更新をトリガーで `calendar_dirty_events` に記録し、書き込み成功後 `after()` で反映する。Google通信が失敗してもアプリの保存は取り消さず、同期待ちを保持する。`calendar_sync_jobs` は予定ごとの版、固定GoogleイベントID、リース、反映済み版とエラーを保存する。再試行は同一IDへの更新を優先し、作成競合を復旧する。削除済み予定を再登録するときは新IDを使用する。

再同期は保存後・接続後・設定画面のボタンから実行する。既存の内部定期同期 `/api/internal/gmail-sync` にも処理を追加している。無操作でも再試行を続けたい場合は、この内部エンドポイントを `GMAIL_SYNC_SECRET` のBearer認証で定期実行する必要がある。未接続・失敗・未同期は設定画面で確認できる。

アプリのDBと暗号化キーは永続保存・バックアップが必要。検証用の一時DBを作り直すと外部予定との対応が失われるため、本運用の接続前に保存先を整える。連携解除では既存のGoogle予定は残る。Google側で手動変更した内容をアプリへ取り込む双方向同期は行わない。次のアプリ側変更・全件同期でアプリの内容を反映する。

## 日程調整からの決定

各候補の見出しと有力候補カードに「この日に決定」を表示する。確認画面で打ち合わせ名と開催方法を選び、候補の開始・終了時刻を引き継ぐ。確定した会議は下段の打ち合わせ欄へ表示し、Google接続後に同期する。○△×は参加可能性の回答なので、確定会議の出欠にはコピーしない。

同じ候補を再送しても1件だけ登録する。決定後も「この日に決定」を押すと、確認画面の「決定する候補日時」で別候補を選べる。現在の決定日時はチェック表示し、ボタンは有効のまま残す。別候補への変更は、この表で作った会議を更新する。変更時は登録済みの打ち合わせ名・開催方法を初期表示する。確定会議が手動編集済みの場合は上書きを拒否し、下段での変更を案内する。下段の会議に未保存の変更がある間は、日程決定ボタンを無効にする。別の打ち合わせを変更・削除しない。

候補の版とイベント範囲、ログイン・同一Origin、会議の版を検証し、決定と会議の作成・履歴・同期依頼は同じトランザクションで保存する。
