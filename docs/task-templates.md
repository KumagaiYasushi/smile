# タスクテンプレートと期限の逆算生成

## 使い方

### 1. 種別ごとのテンプレートを登録する

ログイン後、上部の「タスクテンプレート」へ進み、ベーシックコース・講演会・セミナーのいずれかを選択する。
名称・説明・基準日からの日数・重要設定・有効設定を登録できる。

- 30日前なら `-30`、当日なら `0`、7日後なら `7`。
- 日数は必須で、初期値を自動入力しない。入力範囲は今回の実装では±3650日。
- 標準タスク名や運営上の逆算日数は未提供のため、初期テンプレートは空。
  過去の運営実績に基づく内容を利用者が登録する。
- 全運営メンバーが管理できる。種別は作成後に変更しない。
- 無効にすると以降の生成から除外する。再び有効にできる。
  無効化や編集によって、生成済みタスクの名称・期限・重要設定・進捗は変更しない。

### 2. 新しいイベントを作成する

新規イベントの「種別のテンプレートからタスクを自動生成する」は初期状態で有効。
その種別の有効なテンプレートをコピーし、期限を計算して未着手タスクを作る。
主担当者・協力者は作成後に割り当てる。

- 開催日が1つなら、その日が基準日。
- 複数ある場合は、フォームで「タスク期限の基準日」を開催日の中から選ぶ。
  ベーシックコースの初回／最終回のどちらを使うかをシステムが勝手に決めない。
- 日程未定の場合は、自動生成を外して登録し、開催日の設定後に追加できる。
- 有効なテンプレートがない場合は、イベントだけを登録する。
- イベント登録と生成タスクの保存は同じトランザクション。
  基準日未選択や生成エラーの場合、イベントだけを残さず全体を取り消す。

### 3. 既存イベントへ追加する

イベント詳細 →「タスク・期限管理」→「テンプレートからタスクを追加」で基準日を選ぶ。
「生成予定をプレビュー」でタスク名・期限・重要設定を確認し、「確認して追加する」で確定する。

- イベントに未適用の有効テンプレートだけを対象にする。
- プレビュー後に開催日・種別・テンプレート・適用状況が変わった場合は409で拒否し、再確認を求める。
- 同じ適用操作を再送しても、前回の結果を返して二重生成しない。
- 一度適用したテンプレートは、更新後に再プレビューしても再追加しない。
  生成済みタスクを削除した場合も勝手に復活させない。再登録が必要なら手動で追加する。
- 既存の手動タスクや、変更済みの期限・状態・担当者は書き換えない。

## API

すべて認証必須。書き込みには同一Originが必要。

| メソッド | URL | 内容 |
| --- | --- | --- |
| GET | `/api/task-templates` | 全種別のテンプレート。有効・無効を含む |
| GET | `/api/task-templates?event_type=SEMINAR` | 指定種別で絞り込み |
| POST | `/api/task-templates` | 種別・名称・日数を指定して作成 |
| PATCH | `/api/task-templates/{tid}` | version付き部分更新。無効化はactive=false |
| POST | `/api/seminars/{id}/tasks/template-preview` | base_date（省略可）で生成予定を取得 |
| POST | `/api/seminars/{id}/tasks/apply-templates` | base_dateとpreview_tokenで追加を確定 |

テンプレートの入力：`event_type`, `title`, `description`, `relative_days`, `important`, `active`。
更新時は `version` が必須で、`event_type` は受け付けない。

既存のイベント作成API `/api/seminars` に、任意の `generate_tasks`（boolean、既定true）と
`task_base_date`（開催日に含まれるYYYY-MM-DD）を追加した。
既存クライアントでも、1開催日と有効テンプレートがあれば自動生成する。
有効テンプレートがあるのに日程未定・基準日未選択の場合は400。
その場合は日程を指定するか、`generate_tasks: false` で登録する。
イベント編集PATCHは今回の生成オプションの対象外。

## 保存と整合性

- `task_templates`：種別、内容、相対日数、重要・有効設定、バージョン。
- `task_template_history`：操作アカウント、変更項目、相対日数・設定・版の前後。
  名称・説明の自由記述は監査履歴へ複製しない。
- `task_template_applications`：イベントとテンプレートの一意な適用記録。
  生成時点の版・基準日・相対日数・タスクIDを保持する。タスク削除時も適用記録は残る。
- `task_generation_batches`：イベントと確認トークンごとの生成結果。再試行の重複を防ぐ。
- タスク・適用記録・生成結果・タスク監査は同じトランザクションで保存する。
- イベント削除時は適用記録と生成結果も削除する。テンプレートは物理削除せず、有効設定を使う。

## 残る作業と検証範囲

開催日変更時は [開催日・期限変更](reschedule.md) で変更前後を確認し、各タスクの採用・保持・個別指定を選択できる。
完了済み・固定期限・個別変更済みタスクをどう扱うか（仕様書U11）は、恒久的な業務ルールとして確定しない。
生成時に保存した相対日数を再計算に利用し、後から変更されたテンプレートの日数で既存タスクを上書きしない。

架空の登録済みテンプレートで、AT01相当の種別別自動生成を単体・API結合テストした。
実際の標準テンプレート内容の確認、管理者2名の業務受入、U11の正式運用方針は別途必要。
外部通知やカレンダー連携は実行しない。

`npm test`、`npm run build`、`npm run test:smoke`、`npm run lint` で検証する。
結合テストは独立した一時DBと架空資格情報のみを使用する。
Chromiumの3画面幅で登録・編集・有効切替、新規イベントの自動生成、既存イベントへのプレビュー付き追加を確認済み。実機・他ブラウザーは未確認。[確認結果](ui-validation.md)を参照。
