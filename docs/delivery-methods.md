# 開催方法

2026-11-02の利用者指定に基づき、ベーシックコース・講演会・セミナーのすべてで次の3択を共通に使用する。

| 保存値 | 表示名 |
| --- | --- |
| ONSITE | 現地開催 |
| ONLINE | オンライン |
| HYBRID | 現地開催＋オンライン |

登録・編集の基本情報に必須の「開催方法」を追加。一覧と詳細にも表示する。
イベント種別・参加費・会場記録・既存タスクは、開催方法を変えても自動で変更しない。

SQLiteへ `delivery_method` 列を追加する。既存記録の開催方法は推測せずNULL（画面表示は未設定）とし、ID・日時・参加者を保持する。未設定は移行用の状態であり、画面の選択肢には含めない。

APIは作成・更新で3つの保存値を受け付け、不正な文字列・型・明示的なnullは400。
従来のクライアントとの互換性のため、作成時の省略はNULL、更新時の省略は現在値を保持する。
DBにも3値のCHECK制約を設ける。

SNS文案と講師依頼・参加案内・リマインダーメールの新規生成に開催方法を反映する。
オンライン開催では内部記録の会場を参加者向けの会場として掲載しない。
リマインダーの名刺持参・会場アクセスを前提とする表現を参加方法の問い合わせへ変更する。
会場予約メールは施設への連絡として会場を保持し、開催方法を併記する。

保存済みのSNS文案は自動で上書きしない。開催方法を変更した場合は文案を再生成・確認して保存する。
配信サービスの予約や参加URLの発行・送信は、この変更には含まない。

検証は `npm test`、`npm run build`、`npm run test:smoke`、`npm run test:browser`。
単体テストで旧DBの再実行可能な移行・会場費の保持・案内文、APIで3種別×3方法の保存・変更・不正値拒否、ブラウザーで3つの画面幅における登録・編集・一覧・案内文を確認する。
