# 懇親会

2026-11-02の利用者指定に基づき、各イベントに懇親会の開催有無・日時・場所・参加費を追加した。
ベーシックコース・講演会・セミナーで共通に利用できる。

## 操作と項目

イベント登録・編集画面の「懇親会」で入力し、イベント詳細の「懇親会」で確認する。

| 項目 | 扱い |
| --- | --- |
| 開催 | 未定／開催する／開催しない |
| 開始・終了日時 | 日本時間。終了日時は任意。未確定は空欄で保存可能 |
| 場所・住所 | 最大2000文字。改行可 |
| 参加費 | 1人あたりの円額。空欄は未定、0円は無料、正の整数は有料 |

開催有無を変えても、入力した日時・場所・参加費を削除しない。
「開催しない」の詳細画面では開催有無だけを表示し、保存済みの情報は編集画面から確認できる。
終了日時だけの登録、開始より前の終了、不正日付、負数・小数の参加費は拒否する。

イベント開催日と懇親会日時は独立して管理する。イベント日程を変更しても懇親会日時を自動で移動しないため、必要に応じて編集する。
今回はイベントごとに1件の懇親会を管理する。複数回の懇親会、参加申込・個別出欠・入金・領収書は含まない。

## 保存・API互換性

`seminars.social_gathering` にJSONを保存する追加移行。既存イベントは未定、日時・参加費はnull、場所は空文字とし、既存のID・日付・参加者・更新日時を変更しない。

既存のイベントAPIで `social_gathering` を取得・保存できる。

```json
{
  "social_gathering": {
    "status": "HELD",
    "start_at": "2027-06-01T18:30",
    "end_at": "2027-06-01T20:30",
    "venue": "懇親会場・住所",
    "fee": 5000
  }
}
```

状態値は `UNDECIDED` / `HELD` / `NOT_HELD`。日時は `YYYY-MM-DDTHH:mm` の日本時間をそのまま保存・表示し、端末のタイムゾーンで変換しない。
作成時に懇親会を省略した従来クライアントは未定。更新で省略した場合は現在値を保持する。
PATCHで懇親会の一部の項目だけを送った場合も、その他の現在値を保持して全体の整合性を検証する。
明示的なnull、未知の項目・状態、不正な日時や金額は400。日時・参加費そのものを未定へ戻すには該当項目にnull、場所を消すには空文字を送る。
既存のログイン・同一Originによる書き込み制御を適用する。

## 検証

- 単体・回帰：開催有無、無料と未定、部分更新、不正日時・終了順序・参加費、旧DBの移行と再実行。
- API結合：全3イベント種別の作成・取得・一覧・変更、無関係な更新での保持、不正値拒否、CSRF、イベント日程変更からの独立。
- Chromium：PC・スマートフォン幅で登録・編集・詳細を操作。開催有無の切り替え、無料・未定の表示、保存が503の場合の入力保持と再保存を確認。

実行は `npm test`、`npm run build`、`npm run test:smoke`、`npm run test:browser`。
