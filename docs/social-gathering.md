# 懇親会

ベーシックコース・講演会・セミナー・その他で、イベント登録・編集画面から管理する。
「開催する・開催しない・未定」に加え、「事前・開催日・終了後」を複数選択できる。各区分に複数の懇親会を追加できる。

各懇親会には日本時間の開始・終了日時、お店・場所・住所、予算総額（円）、参加人数、従来の1人あたりの参加費を登録する。予算は総額として管理し、参加費×人数で自動計算・上書きしない。日時・予算・人数・参加費の未定は空欄、0は0円・0名として区別する。

区分の選択を外しても内容を保存し、選び直すと再表示する。「開催しない」にしても内容を保持する。個別の削除ボタンは確認後に削除対象にし、イベントの保存で確定する。
詳細画面では選択中の懇親会を事前→開催日→終了後の順に表示する。同じ区分に複数件ある場合は番号を表示する。
イベント日程の変更では懇親会の日時を移動しない。イベントの参加申込・当日の出欠・入金・領収書の発行は別の管理とする。

## 懇親会ごとの出欠（2026-11-03追加）

イベント登録・編集画面の各懇親会に、研究会講師・研究会サポートメンバー・外来講師・その他の出欠を登録する。名簿は研究会名簿とイベントで選択した外来講師を使い、「その他の参加者を追加」で複数名の氏名を入力できる。
選択肢は打ち合わせと同じ「出席・欠席」の2つ。初期状態は未選択。出席は緑、欠席はグレー、未選択は黒で表示する。各状態の人数を別に表示し、上の参加人数欄は手入力を保持する。
懇親会間、イベント当日の出欠、打ち合わせの出欠は連動しない。懇親会の開始・終了日時を変更すると、その懇親会の出欠だけを未選択へ戻す。名簿の氏名とその他の参加者は保持する。
イベント保存で確定し、登録後はイベントの「編集」から変更する。保存失敗後も入力を保持する。保存済みの氏名・区分・施設は名簿の改名・利用停止後も当時の記録を保持する。新しく選ぶ名簿はサーバーで照合し、クライアント側の氏名を採用しない。
既存の懇親会は出欠なしから始まり、編集画面で名簿を表示する。閲覧だけでは書き込まない。出欠名簿やその他の氏名は、公開用の開催要項PDF・SNS・メール案内に含めない。

## 保存・API

既存の `seminars.social_gathering` JSONへ任意の `timings` と `gatherings` を追加する。既存の単一懇親会は画面で「開催日」の1件として読み取り、従来の日時・場所・参加費を保持する。読み取りや移行だけで既存の更新日時を変更しない。

`timings` は `BEFORE` / `ON_DAY` / `AFTER` の重複しない配列。`gatherings` は最大100件で、各項目は `id`、`timing`、`start_at`、`end_at`、`venue`、`fee`、`budget`、`participants` を持つ。任意の `attendees` は最大1000名で、各項目は `key`、`role`、`member_id`、`name`、`facility`、`response`。区分は `SOCIETY_LECTURER` / `SOCIETY_SUPPORT` / `EXTERNAL_LECTURER` / `OTHER`、出欠は `ATTENDING` / `ABSENT` / null。名簿IDとキーの重複や不正な区分を拒否する。OTHERは名簿IDをnullにし、氏名を必須とする。
IDは重複不可。選択中の区分には1件以上の記録が必要。非選択区分の記録も保持できる。
予算・人数はnullまたは0以上の安全な整数。終了日時だけの登録、開始より前の終了、不正日付・小数・負数・未知の項目は拒否する。

従来のルート階層の日時・場所・参加費は、選択中の先頭の記録に同期する。従来クライアントによるこれらの部分更新も先頭の1件へ適用し、他の懇親会を変更しない。開催有無だけの変更は各記録を保持する。
作成時の省略は未定、更新時の省略は現在値の保持。ログイン・同一Originを確認し、入力不備時はイベント・出欠・昼食の一括保存を取り消す。

## 検証

単体テスト・API結合テストで、全区分の独立保存、無料・未定・0名、区分解除後の保持、旧記録・旧クライアントの互換性、不正値・CSRF、無関係な編集と日程変更での保持を確認する。
PC・スマートフォンでは、複数区分と同一区分の複数登録、予算・人数の編集、非選択からの再表示、保存エラー後の入力保持を確認する。

出欠追加の単体・API・3画面幅のブラウザー検証では、4区分・その他複数名、各懇親会の独立性、登録時と登録後の保存、出欠の色、日程変更時の未選択へのリセット、保存エラー後の入力保持、名簿照合・公開要項からの除外を確認する。
