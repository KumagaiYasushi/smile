# 会場台帳

2026-11-02の利用者指定に基づき、借りる会場を繰り返し使える台帳として管理する。

## 操作

上部メニューの「会場台帳」から「＋ 会場を登録」を選ぶ。会場・部屋ごとに登録できる。

| 項目 | 内容 |
| --- | --- |
| 会場名・部屋名 | 会場名は必須。各200文字以内 |
| 住所・アクセス | 各2000文字以内 |
| 窓口担当者・電話番号・メールアドレス | 連絡先の管理 |
| 公式サイト・予約ページ | http／https URL。認証情報を埋め込んだURLは不可 |
| 定員 | 0以上の整数。空欄は未定 |
| 参考料金・料金の単位や条件 | 円単位の整数。空欄は未定、0は0円。「1時間」「半日」などを別記 |
| 設備・備品 | プロジェクター等、2000文字以内 |
| 予約方法・キャンセル条件、備考 | 各2000文字以内 |
| 利用状態 | 利用候補／利用停止 |

会場名・部屋名・住所・窓口担当者で検索できる。検索文字の `%` や `_` はワイルドカード扱いせず文字として検索する。
「利用状態」で利用候補・利用停止・すべてを切り替える。
利用しなくなった会場は「利用停止にする」で選択肢から外せる。「利用候補に戻す」で再開できる。参照と履歴を残すため、台帳の完全削除は提供しない。

## イベントとの連携

ベーシックコース・講演会・セミナーの登録／編集画面の「会場」で「会場台帳から選択」を使う。
選択時に会場名・部屋名・住所をイベントへ転記する。転記した文字列は直接編集できる。
参考料金は自動で会場費に設定しない。料金の単位と実際の利用条件を確認し、必要な場合に「参考料金を会場費に入力」で転記する。
台帳の管理リンクは別タブで開くため、イベントの入力を残して台帳を登録し「台帳を再取得」して選べる。

`seminars.venue_id` に台帳IDを、既存の `venue`・`venue_fee` にイベント用の保存値を持つ。
台帳の名称・住所・参考料金を変更しても、過去や編集中のイベントの保存値を自動で変更しない。
最新情報へ更新したい場合は、選択後に「会場情報を再転記」を使う。
「台帳との紐付けなし」を選んでも、入力済みの会場文字列や会場費は消さない。

利用停止の会場は新たに紐付けできない。すでに紐付いているイベントの編集では、その会場を保持したまま保存できる。
台帳の読み込みに失敗しても、会場文字列は直接入力できる。
オンライン開催でも内部記録の配信拠点として選択できる。既存のルールに従い、オンライン開催の案内文には物理会場を載せない。

既存イベントの自由記入会場はそのまま保持し、台帳IDはnullとする。自由記入文字列から名称と住所の境界や同一施設を推測して自動登録はしない。
施設への実際の予約・問い合わせ・空室確認はこの機能では行わない。

## 保存・履歴・API

`venues` と `venue_history` を追加する。`seminars.venue_id` の追加移行は繰り返し実行でき、既存のID・日程・参加者・会場・更新日時を変えない。
会場の登録・編集・利用停止と履歴記録は同じトランザクションで保存する。履歴記録が失敗した場合は全体を戻す。
同時編集は `version` で検出し409とする。入力を保持するので、必要な内容を控えてキャンセルし「最新情報を取得」して編集し直す。
履歴は直近100件。操作アカウント、変更項目、変更前後の利用状態・定員・参考料金を記録し、住所・窓口氏名・連絡先・備考を複製しない。

| API | 用途 |
| --- | --- |
| GET `/api/venues?query=...&status=ACTIVE` | 検索。statusはACTIVE／INACTIVE／ALL、既定はACTIVE |
| POST `/api/venues` | 会場登録 |
| GET `/api/venues/{id}` | 会場情報と変更履歴 |
| PATCH `/api/venues/{id}` | 部分更新。`version`必須 |

入力項目は `name`, `room`, `address`, `access`, `contact_person`, `phone`, `email`, `website`, `capacity`, `reference_fee`, `fee_unit`, `equipment`, `booking_notes`, `notes`, `active`。
イベントAPIは追加の `venue_id` を受け付ける。作成時の省略はnull、更新時の省略は保持、明示的なnullは紐付け解除。
不正ID、存在しない会場、新たな利用停止会場の選択を400で拒否する。
全APIはログイン済み運営メンバー向け。書き込みに同一Originを必須とし、会場台帳の返却値はキャッシュしない。

## 検証

`npm test`：検索・利用状態・部分更新・不正入力・競合・履歴・監査失敗時のロールバック・旧DB移行。
`npm run test:smoke`：全3イベント種別での会場選択、台帳変更時のイベント保存値保持、利用停止・再開、認証・CSRF。
`npm run test:browser`：PC・スマートフォン幅で会場登録・検索・入力保持・編集競合・利用停止失敗からの再試行、イベントへの転記、参考料金の明示的入力、利用停止後の既存イベント編集。
