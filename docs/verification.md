# 操作検証ページと専用環境

アプリ内の `/verification` に、ベーシックコース・講演会・セミナーのサンプルを開く案内ページを追加した。
これは公開済みのURLではない。現在のクラウド環境に外部プレビューURLを発行する機能はなく、利用者の公開先も未定のため、共有URLはまだ発行していない。

公開先候補として、Freeプランを指定したRender向け構成を追加した。アカウント作成後の手順と一時保存の条件は [render-verification.md](render-verification.md) を参照。実際のRenderデプロイと共有URLの発行は未実施。

## 準備と起動

作業ディレクトリ `/workspace/smile` で、実際に使う検証用ログインメールを指定する。

```sh
npm run verification:setup -- you@example.com
npm run verification:start
```

初回だけパスワードを非表示で入力する（12〜128文字）。パスワードは引数やソース、チャットへ書かない。
初回ユーザーは運営メンバーとして作成する。認証を省略する入口や共通の固定パスワードは設けない。
起動後にログインし、上部メニューの「検証ページ」を選ぶ。ページのパスは `/verification`。
既定では3300番ポート、ループバック限定で開発サーバーを起動する。これは外部から開ける公開URLではない。

準備コマンドを再実行しても、サンプル・パスワード・キー・手動編集を上書きしない。
同じメールがすでに登録されていればパスワードの再入力は不要。サンプルを削除した場合も自動で復活させない。

## 通常データとの分離

- 専用DB・キー・識別マーカーは `data/verification/` に保存する。
- 準備スクリプトは通常の `data/seminars.db` と `.env.local` を読み込まない。Next.js起動時も専用DB・暗号化キー・Originを明示し、通常設定より優先する。
- `SMILE_DATA_DIR` を継承していても専用ディレクトリへ上書きし、通常DBにサンプルを投入しない。
- 既存DBがあるのに検証用マーカーがないディレクトリを拒否する。既存業務DBを検証用として転用しない。
- `runtime.json` の暗号化キーは権限0600で保存し、表示しない。パスワードの平文は保存しない。
- `data/` はGitとNext.jsの配布物から除外済み。専用データ・秘密設定はコミットしない。
- 通常起動では検証メニューを表示せず、ログイン後の `/verification` も404とする。
- サンプル生成はCLIのみ。未認証でサンプルを書き込めるAPIを設けない。

別の保存先で試す場合は `SMILE_VERIFICATION_DATA_DIR` を明示して、準備と起動で同じ値を使う。
自動テストは毎回一時ディレクトリ・ランダムなパスワードを使い、終了時にその一時データだけを削除する。

## 外部から開くための次の準備

外部閲覧用には、Node.js・SQLiteを実行できるサーバーとHTTPSの公開先が必要。再起動後も編集内容を維持する場合は、永続ディスクを利用する。
公開先を決めたら、そのサーバーで準備コマンドを実行し、次の値を設定して起動する。

```sh
npm ci
npm run build
SMILE_VERIFICATION_HOST=0.0.0.0 \
SMILE_VERIFICATION_ORIGIN=https://your-test-host.example \
npm run verification:start -- --production
```

ホスト名は実際のものへ置き換える。`SMILE_VERIFICATION_ORIGIN` は末尾スラッシュなしのHTTPS Origin。
HTTPSはサーバーのリバースプロキシ等で終端し、そのOriginからNode.jsのポートへ転送する。
`PORT` で待受ポートを指定できる。DBとキーは永続ディスク上の専用ディレクトリに置く。
`--production` ではHTTPS Originを必須とし、通常のSecure Cookieと同一Originの書き込み制御を維持する。
起動スクリプト自体はドメイン取得、サーバー契約、HTTPS証明書や外部の公開経路を作成しない。

## 確認コマンド

```sh
npm test
npm run build
npm run test:smoke
npm run test:verification
```

単体テストでDB分離、初期化の重複防止、手動編集・パスワード保持、不正な既存DBの拒否を確認する。
検証環境の実起動テストは3301番を使用し、ログイン必須、PC・スマートフォン幅の案内ページ、全3サンプルの外来講師向け昼食の編集、ログアウトを確認する。
画像はGitで無視される `test-results/verification/desktop.png`・`mobile.png` に保存し、資格情報を含むログイン画面や通信トレースは保存しない。
