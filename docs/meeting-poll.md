# 打ち合わせの日程調整表

イベントを保存した後、イベントメニューの「打ち合わせ」→「打ち合わせの日程調整」を開く。開催確定後の打ち合わせ・出欠とは別に、1イベント1つの日程調整表を設ける。

1. 「候補日時を設定・変更する」で表の名前と複数の候補を登録する。候補は30件まで。日付・開始時刻は必須、終了時刻は任意。同日内で開始より後の終了時刻を選ぶ。時刻は日本時間・10分刻み。新規候補の初期値は開始20:00・終了22:00。保存済みの時刻は変更しない。保存後は日時順。
2. 名簿の有効な研究会講師・サポートメンバー（初期10名）を行、候補日時を列に表示する。名簿の追加・改名も再取得で反映する。
3. ログインした運営メンバーが「回答する方のお名前」で自分の名前を選び、○参加可能・△調整が必要・×参加不可をクリックする。選択ごとにそのセルだけ保存する。－で未回答に戻せる。名前を選ぶまでは閲覧用。
4. 各候補の○△×と未回答の人数を集計する。「最新の表を取得」で他メンバーの最新回答を確認する。
5. 決定した日程は、下段の「打ち合わせの登録（確定した日程）」へ登録する。候補日時はHOMEの確定予定に表示せず、確定した打ち合わせの出欠へも転記しない。

スマートフォンでは表内だけを左右・上下にスクロールできる。氏名列と日時・集計の見出しを固定する。○△×は文字と色を併用。

## アカウントと回答者

既存の運営メンバーのログインを必須とする。名簿とログイン用アカウントは現在別管理のため、選んだ名簿の氏名を回答者として扱う。本人のアカウントと氏名を自動で対応付ける制限はない。ログイン中の運営メンバーは代理入力もできる。外部公開・ログイン不要の回答URLは追加していない。実際に保存を行ったアカウントIDは履歴へ記録する。

## 同時操作と変更

- 回答は候補×名簿IDのセルごとの版で比較し、違うメンバーや違う候補の回答は上書きしない。同じセルへの古い更新は409で拒否する。
- 候補の追加・名称変更では既存回答を保持する。候補の日時を変更した場合はその候補の回答だけを削除し、版を更新する。候補削除もその列だけ削除する。保存済みの候補を変更・削除すると確認ダイアログを表示する。
- 候補編集は表の版で比較し、回答の保存だけでは表の版を変えない。候補日時の変更後、古い画面の回答は候補の版で拒否する。
- 利用停止メンバーに回答がある場合は履歴として行を残すが、新規回答・集計の対象から外す。
- 失敗時は画面の入力を保持する。保存内容と操作アカウントの履歴は同一トランザクション。イベント削除時は候補・回答・履歴も削除する。

## API・保存

`/api/seminars/:id/meeting-poll` のGETで表を取得、PUTで候補・名称を保存、PATCHで1セルの回答を保存する。ログイン必須、書き込みは同一Originを確認する。別イベントの候補、不正日付・1分刻みの時刻・余分なフィールドは拒否する。

保存先は `meeting_polls`、`meeting_poll_candidates`、`meeting_poll_answers`、`meeting_poll_history`。既存の `event_meetings` は変更しない。

## 有力候補の強調

有効な名簿の回答で、○の人数が最も多い候補を選ぶ。同数なら△の人数が多い候補を優先し、同率はすべて表示する。○も△もない候補は推薦しない。未回答は参加可能に数えず、利用停止メンバーは集計から除く。

表の上部に候補日時・○△×の人数・未回答人数を大きく表示し、該当列の見出し・集計・回答セルを緑色で強調する。回答の保存・再取得に応じて再計算し、日時順は保持する。表示は現時点の候補であり、開催確定の登録は別に行う。
