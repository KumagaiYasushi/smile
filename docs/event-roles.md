# イベントの役割担当

2026-11-03追加。研究会講師・研究会サポートメンバーの名簿から、イベントごとに役割担当を登録する。単回・複数回・日程未定と全4イベント種別で使える。

## 登録と変更

新規イベント登録・編集画面の「役割担当」を開く。登録後はイベントメニューの「役割担当」からも変更できる。各役割を開くと名簿のチェックボックスが表示され、複数人を選べる。同じ方を複数の役割に選ぶこともできる。

| 区分 | 役割 |
| --- | --- |
| 準備役割 | 会場担当、外部講師担当、昼食担当、会計担当、告知WEB担当、協賛担当 |
| 当日役割 | 受付、総合司会、座長、懇親会 |

役割は未割当でも保存できる。最初から誰かを割り当てない。準備役割はイベント共通、当日役割は開催日ごとに登録する。役割を選んでも出欠を出席にせず、当日・打ち合わせ・懇親会の出欠とは分けて扱う。タスクの主担当者（ログインアカウント）への自動割当・通知・メール送信も行わない。

イベント登録・編集ではイベントとまとめて保存し、登録後の専用画面では「役割担当を保存」で確定する。保存失敗時は入力を保持する。別操作の更新と競合した場合は上書きせず、未保存の入力を保持する。「担当・名簿を再取得」は未保存の変更を破棄する確認後に最新値へ戻す。

役割を編集していないイベント保存では役割情報を送らず、別画面での更新を保持する。名簿取得に失敗した場合は役割の選択を無効にし、再取得を案内する。

## 名簿との関係

氏名・講師／サポートの区分は、担当登録時にサーバー側で名簿から確定する。既存の割当は保存時の氏名・区分を保持し、名簿の改名後は現在の名簿名も参考表示する。
利用停止した方の保存済み割当は保持し、解除できる。新しく別の役割へ利用停止メンバーを追加することはできない。新しく選ぶ名簿のバージョンが更新されていた場合は再取得を求める。名簿はログインアカウントとは別のため、氏名登録でアカウントを作成しない。

## 保存・API

- GET `/api/seminars/{id}/roles` は10役割の `assignments`、担当全体の `version`、研究会名簿 `members`。未登録は全役割が空配列、版0。
- PUT `/api/seminars/{id}/roles` は `{version, assignments}` を送り、10役割を一括保存する。各役割の配列には `{member_id, member_version}` を指定する。任意の氏名・区分・操作アカウントを入力として受け付けない。
- キーは `VENUE` / `EXTERNAL_LECTURER` / `LUNCH` / `ACCOUNTING` / `WEB` / `SPONSORSHIP` / `RECEPTION` / `MC` / `CHAIR` / `SOCIAL`。各役割最大1000名、同一役割のID重複は不可。役割をまたぐ同一IDは可。
- イベント登録・編集APIでは任意の `registration.roles` に同じ形式を指定する。省略時は既存情報を保持する。
- `event_role_assignments` はイベントIDごとに担当者の記録、版、操作アカウント、更新時刻を保存する。`event_role_history` は操作アカウント・日時・担当IDと版の前後を記録し、氏名を履歴へ複製しない。イベント削除時は関連する担当と履歴も削除する。
- ログイン・同一Origin・有効な操作アカウントを確認する。不正形式・未知ID・利用停止メンバーの追加は400、担当や名簿の競合は409、存在しないイベントは404。返却値はキャッシュしない。
- 新規登録・編集では、イベント・基本タスク・出欠・昼食・打ち合わせ・役割・監査を同一トランザクションで保存し、途中の失敗時は全体を戻す。担当者名簿は公開用の開催要項PDFやSNSへ含めない。

単体・APIで10役割への複数人・兼任、全イベント種別、登録後の追加変更、名簿の改名・利用停止、版・イベント範囲・認証・CSRF、不正値、監査失敗と一括保存のロールバック、イベント削除を確認する。ブラウザーでは3画面幅で新規登録、保存失敗後の入力保持、登録後の変更、競合と再取得、イベント編集からの変更を操作する。

## 出欠による当日役割の制限

新規登録・編集画面では「イベント当日の出欠」を先に表示し、その後で役割担当を選択する。出欠と当日役割の開催日選択は連動する。選択中の日が欠席のメンバーは、その日の当日役割でグレー表示となり、新しく選択できない。他の日の出席・未登録状態には影響しない。午前のみ・午後のみ・未登録のメンバーは選択できる。準備役割は出欠で制限しない。

同じ登録・編集画面で、選択済みの担当者を欠席へ変更すると、その日の当日役割だけを解除する。他の日の担当と準備役割は保持する。出欠画面など別操作で欠席となった既存担当は、グレー表示のまま解除を案内し、担当のチェックは解除操作だけを可能にする。保存時もサーバーで欠席日への割当を拒否する。

APIのGETは `attendance` と `day_assignments` を返す。PUTの `day_assignments` は開催日をキーにし、`RECEPTION` / `MC` / `CHAIR` / `SOCIAL` の4項目を指定する。日程未定のキーは空文字列。`assignments` の準備役割は共通の設定、当日役割は現在の日程に割り当てられたメンバーを重複なくまとめた表示用の情報となる。

従来のイベント共通の当日役割は、既存の各開催日に引き継ぐ。日別保存後に追加された日程は未割当とし、他の日から自動コピーしない。旧日程の担当記録は保持する。旧形式のAPI入力（日別指定なし）は、現在の各開催日に同じ担当者を割り当てる互換動作を保つが、いずれかの日が欠席なら保存を拒否する。
