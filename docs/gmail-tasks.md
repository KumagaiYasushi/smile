# タスクの文面・Gmail連携・返信確認

2026-11-03追加。実メールを使う接続は利用者のGoogle設定後に行う。単体・結合テストは合成データと模擬Gmailで行い、実際の送信・実アカウントのOAuth認証は未実施。

## 画面の使い方

1. システム全体のメニューの「Gmail連携」を開く。未設定でも各タスクの文面確認・コピーは使える。
2. 接続後、イベントの「タスク・期限管理」で「文面を確認」を押す。宛先は必ず確認して入力する。氏名だけからアドレスを推測しない。
3. 件名・本文を編集し「文面を保存」。開閉では未保存の入力を保持する。「文面を再取得」は未保存の変更を破棄する確認後に最新値へ戻す。資料一括依頼には略歴・プロフィール写真・抄録300文字・抄録800文字の4点が入る。登壇依頼や参加者確認、任意タスクにも初期文面がある。
4. 「文面をコピー」で宛先・件名・本文をコピーできる。「Gmailで文面を開く」はGoogleの作成画面を開くが、アプリ外で送ったものは自動記録しない。
5. 「Gmailで送信」を押し、宛先と件名の確認に同意すると接続中のGmailから送る。1タスクにつき1件の宛先・1回の依頼を扱う。参加者全員への一斉送信は行わない。
6. 成功後は送受信表示を「送信済み」、未着手の作業状態を「進行中」にする。依頼先からの返信を確認すると「受信済み」、未着手・進行中の作業状態を「確認待ち」にする。完了済みの作業状態は戻さない。受信だけで資料の充足・内容確認が完了したとは扱わない。

送信済みの文面・宛先は変更しない。再依頼が必要なら別タスクを作り、履歴を分ける。送信がタイムアウトした場合は「送信結果の確認待ち」とし、自動再送しない。「送受信を確認」でGmailの送信済みを照合する。結果が確認できない間はGmail側でも確認する。

## Google Cloudの設定（初回）

1. Google Cloudコンソールでプロジェクトを選び、Gmail APIを有効にする。
2. Google Auth Platformでアプリ名・連絡先・対象ユーザー等の同意画面を設定する。テスト中は利用するGmailアドレスをテストユーザーに追加する。
3. データアクセスで `https://www.googleapis.com/auth/gmail.send` と `https://www.googleapis.com/auth/gmail.readonly` を追加する。Googleが示す許可内容を確認する。
4. クライアントをウェブアプリケーションとして作り、承認済みリダイレクトURIに公開先の `/api/gmail/callback` を登録する。この検証サイトでは `https://smile-verification.onrender.com/api/gmail/callback`。正確な値はアプリのGmail連携画面にも表示する。
5. RenderのサービスのEnvironmentへ `GMAIL_CLIENT_ID` と `GMAIL_CLIENT_SECRET` を登録する。これらの値をチャットへ送らない。`APP_ORIGIN` は公開先のHTTPS Origin、`AUTH_MFA_KEY` は既存の64桁16進暗号化キーを使う。検証用起動スクリプトでは公開先と専用暗号化キーを準備済みなので上書きしない。
6. 再配置後、アプリの「Gmail連携」→「GoogleでGmailを接続」で認証する。コールバックの完了画面からアプリへ戻る。

Googleのテスト公開ではGmail権限の更新トークンが通常7日で期限切れになる。継続運用はGoogleの公開・審査要件（読み取り権限は制限付きスコープ）を確認する。組織のポリシーで許可できない場合は管理者の設定が必要。許可不足・失効時は再接続を案内する。

## 返信を自動確認するタイミング

タスク画面が表示中なら1分ごとに確認する。「送受信を確認」は手動実行。1回あたり最大10件を最終確認時刻の古い順に処理し、件数が多い場合も順番に確認する。非表示タブでは自動確認を止める。
対象は送信アカウントに紐づくアプリ内の依頼だけ。送信したGmailスレッド内で、宛先と同じFrom、送信後の日時、送信メールのMessage-IDを参照する返信を確認する。送信済み・下書き・迷惑メール・ゴミ箱・自動返信、別の差出人や参照のないメールを受信済みとしない。添付・本文を読み取って資料を自動検収しない。別Gmailへ接続し直しても、以前の送信メールを別アカウントで照合しない。

画面を閉じている間も確認する場合：

- RenderのEnvironmentへ32文字以上のランダムな `GMAIL_SYNC_SECRET` を設定する。
- 運用する外部スケジューラーから数分おきに `POST https://公開先/api/internal/gmail-sync` を呼ぶ。ヘッダーは `Authorization: Bearer <GMAIL_SYNC_SECRET>`。URLへ秘密値を入れない。
- エンドポイントは有効な各運営アカウントの接続で返信を照合する。送信は行わない。未設定時503、不正認証401、部分失敗502。
- このリポジトリから外部スケジューラーは作成しない。Render無料サービスは休止するため、常時運用は稼働条件も含めて設定・確認する。

## 保存・保護

Gmail接続は運営アカウントごと。アクセス・更新トークンはAES-256-GCMで暗号化して保存する。OAuthは使い捨てstate・ブラウザー限定のHttpOnly/Secure/Lax Cookie・PKCE・10分期限で保護する。Googleから戻る際はSameSite Strictの業務セッションに依存せず、stateで開始時の有効アカウントを照合する。API・画面へトークンを返さない。
`gmail_connections`、`gmail_oauth_states`、`event_task_mail` を追加。メールには文面、宛先、送信元、版、送信アカウント、Gmail ID・スレッドID・RFC Message-ID、送受信日時を記録する。イベント・タスク削除時は関連記録を削除する。文面編集は版を照合し、送信をDBで先に確保して並行送信を防ぐ。受信本文は保存しない。
業務APIはログインと同一Originを確認。コールバックはOAuth state、定期同期は専用Bearerで確認する。Googleのエラーや資格情報をログ・利用者向けメッセージへ出さない。
連携解除ではこのアプリの資格情報を削除し、以降の照合を止める。Google側の許可も取り消したい場合はGoogleアカウントの接続管理を使う。

## API

- GET/DELETE `/api/gmail`：接続状況／連携解除。POST `/api/gmail/connect`：同意画面へのURLとstate Cookie。GET `/api/gmail/callback`：接続完了。
- GET/PATCH `/api/seminars/{id}/tasks/{tid}/mail`：初期または保存文面の確認／版付き保存。
- POST `/api/seminars/{id}/tasks/{tid}/mail/send`：保存済み版の確認後に1回送信。
- POST `/api/gmail/sync`：ログイン中の送信アカウントの依頼を照合。
- タスクGETは送受信状態と当日の短い進捗コメントを返す。コメントはタスクの完了・期限・送受信記録から生成し、日付は日本時間。画面表示・再取得・1分間隔の確認で更新する。コメント生成自体はメールを送らない。
