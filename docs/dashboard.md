# イベント横断のタスクダッシュボード

## 使い方

ログイン後、上部の「ダッシュボード」から開く。
全イベントの未完了タスクをまとめて集計し、件数カードを押すと該当タスクへ絞り込める。

| 区分 | 対象 |
| --- | --- |
| すべての未完了タスク | 状態が「完了」以外 |
| 期限超過 | 期限が日本時間の今日より前 |
| 確認待ち | 状態が「確認待ち」 |
| 主担当未割当 | 主担当者が未設定 |
| 直近の重要タスク | 重要設定があり、期限が今日から指定日数後まで |
| 自分が関わるタスク | 自分が主担当または協力者 |

同じタスクは複数区分に該当し得る。ただし主担当と協力者の両方に登録されていても、「自分が関わる」の中で二重に数えない。
「完了」は全区分から除く。期限未設定のタスクは、全件・確認待ち・未割当・自分の担当には表示できるが、期限超過と直近の重要タスクには含めない。

重要タスクの期間は、今日〜3日後・7日後・30日後から選択する。初期表示は7日後まで。
今日と終端日の両方を含む。例として11月2日基準で「今日〜7日後」は11月9日まで。
これは画面の絞り込み条件で、通知時期などの業務ルールは変更しない。

一覧は期限の早い順、同日なら重要タスクを先に表示する。期限未設定は最後。
同条件ではタスクID順で安定させ、50件ずつページを切り替えられる。
絞り込みや期間を変えると最初のページへ戻る。

「イベントのタスクを開く」から、状態・担当者・期限の編集画面へ移動できる。
ダッシュボード自体ではデータを書き換えない。
他の人の編集を確認する場合や、日本時間の日付が変わった場合は「最新の内容を取得」を押す。

## 集計の範囲

- 現在のイベントに開催中／終了などの状態区分がないため、全イベントが対象。
  表示イベント数は、タスクのないイベントも含む。
- 主担当が利用停止アカウントの場合、未割当へ自動変更せず、一覧に「利用停止」と表示する。
  担当者の変更はタスク管理から行う。
- 未割当と利用停止アカウントは別の状態。今回の未割当件数には主担当未設定だけを含める。
- 既存の5項目チェックリストは今回のタスク集計に合算しない。
- 通知センター・外部連携障害・LINE通知などの情報は今回の対象外。
  外部サービスへの送信や接続も行わない。

## API

`GET /api/dashboard`（認証必須、no-store）

| パラメーター | 値 | 既定 |
| --- | --- | --- |
| filter | ALL / OVERDUE / IN_REVIEW / UNASSIGNED / IMPORTANT / MINE | ALL |
| days | 3 / 7 / 30 | 7 |
| page | 1〜100000の整数 | 1 |

余分なパラメーター・重複パラメーター・不正値は400で拒否する。
「自分」は認証済みセッションのアカウントIDで判定する。
クエリで別ユーザーを指定することはできない。

レスポンスには日本時間の基準日・終端日・イベント数・区分ごとの件数、選択条件、該当総数、ページ情報、タスク一覧を含む。
区分の件数は選択フィルターやページにかかわらず全対象から計算する。
件数と一覧を同じ読み取りトランザクションで取得する。

タスクの減少で要求ページが存在しなくなった場合は、有効な最終ページへ補正する。
0件なら1ページ目の空一覧と件数0を返す。
タスク状態の変更、期限の自動更新、業務監査への書き込みは行わない。
取得エラー時は、前の条件の一覧を新しい条件の結果として表示しない。

## 検証と残る作業

- `npm test`：複数イベントの集計、本人の主担当・協力者判定、重複排除、日本時間の日付境界、期間の終端、ページ切り替え、空一覧、読み取りによるデータ保持。
- `npm run build`：画面とAPIのビルド・型検査。
- `npm run test:smoke`：一時DBと架空アカウントで未認証拒否、実APIの条件指定、完了後の件数反映、余分な本人指定の拒否を検証。
- `npm run lint`：既存メール画面のHook依存配列警告1件は継続。

Chromiumの3画面幅で本人タスクのカード絞り込みと期間選択を確認済み。ページ切り替えは単体テストで確認。実機・他ブラウザーは未確認。[確認結果](ui-validation.md)を参照。
運営側の業務受入、イベントの状態管理、通知・連携障害との統合は後続開発で扱う。
