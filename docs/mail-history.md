# メール送信履歴

システムメニューの「メール送信履歴」で、タスク依頼・申込受付・入金確認メールを送信元アカウントやイベントをまたいで時系列に表示する。イベントメニューの「このイベントの送信履歴」は、そのイベントで絞り込んで開く。

- 初期表示は新しい順。「古い順」へ変更できる。日時は日本時間（秒まで）。
- イベント、メールの種類、宛先・氏名・件名で絞り込める。
- 50件ずつページ送りし、送信済みの全記録を表示する。直近100件等の打ち切りはない。
- 送信日時・送信元・宛先・イベント名・件名を一覧に表示し、「本文・添付を確認」で送信本文と領収書PDFを開く。
- 本文・宛先・件名・イベント名・添付は送信時点の記録。タスクや参加者を編集・削除したり、イベントを削除しても送信済みの履歴は残す。元のイベントがない場合はその旨を表示し、イベントへのリンクを外す。
- 送信処理中・結果不明は送信済みとして表示しない。「接続中のGmailで送信結果を確認」は、送信時のMessage-IDとGmailアカウントを照合するだけで再送信しない。

新しい送信は、Gmailへ送る前に本文・宛先・添付の記録を確保し、送信確認後に送信済みへ確定する。結果不明で元のタスクが削除された場合も、保管した記録でGmailの送信済みを確認できる。既存のGmail同期・定期同期からも確認する。

既存の送信済みタスク・参加者メールは、残っている記録から初回表示時に取り込む。導入前にすでに削除された記録や、このシステムを経由せずGmail等から送ったメールは復元・収集しない。導入前の領収書添付は、残っている発行時の領収書情報から再生成する。

APIは `/api/mail-history`（GET：絞り込み・ページ送り、POST `{action:"sync"}`：現在の送信アカウントの結果確認）、`/api/mail-history/:id`（本文）、`/api/mail-history/:id/attachment`（PDF）。すべて運営メンバーのログインが必要。操作には同一Originも確認する。OAuthの資格情報は返さず、PDFは認証付きで取得する。

履歴は `outbound_mail_history` に保存する。元データとは別に送信記録を保持するため、永続保存・バックアップの対象に含める。
