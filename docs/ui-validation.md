確認日：2026-11-02（日本時間）。架空データと一時DBのみを使用。
Chromium 154.0.8037.57、Playwright 1.62.1、Node.js 24.19.0で検証した。

単体・回帰85テスト、API結合テスト、ビルド・型検査も成功。
Lintはエラー0件、既存メール画面のHook依存配列警告1件。

## 見つかった問題と修正

| 問題 | 修正 |
| --- | --- |
| イベント入力欄や参加者フォームの項目名と入力欄が未関連付け | 安定したIDとラベルを関連付け、複数入力はグループと個別名を設定 |
| 選択肢の文字列まで入力欄の名前に含まれる箇所 | 選択欄の読み上げ名を画面の項目名に固定 |
| 会場フォームの再描画でテキストエリアの値がラベル文字列に混ざる | テキストエリアの読み上げ名を項目名に固定し、保存失敗後や競合時も入力を確認できるよう修正 |
| スマートフォンの参加者テーブルで氏名・操作が横スクロール先へ隠れる | 768px未満はカード表示にし、主要操作を画面幅内へ配置 |
| 参加者フォームが通常のオーバーレイで、キーボード操作の境界が不明確 | ネイティブdialog、見出し関連付け、画面内スクロール、Escape制御を追加 |
| 保存・更新・削除の失敗レスポンスを成功として扱う | HTTPエラーを検出し、成功時だけ画面データを更新。入力とエラー表示を保持 |
| 開催回数の補足文追加で入力欄とラベルが関連付かなくなる | 補足文を入力グループの外へ配置し、ラベルの関連付けと必須選択を実ブラウザーで確認 |
| 領収書の印刷へ管理ヘッダー・メニュー・フッターが入る | 領収書の印刷時だけ管理UIを非表示にし、余白と用紙方向を調整 |
| 発行日の初期値がUTC日付で、日本時間の早朝に前日になる | サーバーで日本時間の暦日を発行時に保存し、再表示も保存値を使用 |

## 再実行

```sh
npm ci
npm run build
npm run test:browser
npm run test:verification
npm run test:hosted
```

この環境ではシステムの `/usr/bin/chromium` と `pdfinfo` を使用する。
Chromiumの場所が異なる場合は `PLAYWRIGHT_CHROMIUM_EXECUTABLE` で実行ファイルを指定する。
ブラウザーのダウンロードや証明書検証の無効化は行わない。
子プロセス・ローカルポートの使用がEPERMで拒否される場合は、そのコマンドの対応した実行許可を使用する。

スクリプトは3200番に独立サーバーを起動するため、同ポートが空いている必要がある。
プロダクションビルドを起動して確認し、通常の開発サーバーや既存のDB・ユーザー設定は使用しない。
資格情報は毎回ランダム生成し、ブラウザーと一時サーバーの終了後、一時DBを削除する。
Webページのリクエスト先も一時サーバーだけに制限する。

結果JSON・画面画像・架空の領収書PDFは、Gitで無視する `test-results/browser/` に出力する。
パスワードやMFA登録キーを含み得るトレース・HARは保存せず、ログイン画面のスクリーンショットも撮影しない。
実ユーザーの資格情報を使うスクリプトへ変更しない。

## 残る確認

- iOS・Android実機、Safari／WebKitなどChromium以外での確認。
- OS標準の日付選択画面やソフトウェアキーボード、スクリーンリーダー実機での確認。
- 実際のプリンターと印刷ダイアログの設定別の確認。
- 大量データ時の画面負荷、業務担当者による受入、未実装機能の追加。
- 正式なテスト／本番WEB環境と認証サービスでの確認。

本検証は現在のクラウド実行環境での結果。クラウド環境のPublishや本番アプリの公開が成功したことは示さない。
