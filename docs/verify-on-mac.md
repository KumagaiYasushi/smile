# Macでこれまでの実装を確認する

本番公開せず、自分のMacの中だけで動かす確認用です。実参加者情報、実際のGmail、LINE、Googleデータは使いません。

## 1. 初回準備

1. [GitHubの確認用ブランチ](https://github.com/KumagaiYasushi/smile/tree/codex/mac-review-20261101)を開き、緑色の **Code → Download ZIP** でMacへ保存します。必要なら、ご自身のGitHubアカウントでログインしてください。
2. ZIPをダブルクリックして展開します。GitHubから取得した場合は`smile-codex-mac-review-20261101`等のフォルダー名になります。すでに同名のフォルダーがある場合は上書きせず、別の場所に展開してください。以前の確認用ZIPの`smile-review`フォルダーでも起動方法は同じです。
3. [Node.js公式サイト](https://nodejs.org/)から **Node.js 24** をインストールします。Macの種類に合うインストーラーを使用してください。すでに24があれば不要です。
4. アプリケーション → ユーティリティ → **ターミナル**を開きます。
5. ターミナルに `cd `（cdの後ろに半角スペース）と入力し、展開したソースのフォルダーをターミナルへドラッグしてReturnを押します。
6. 次を入力してReturnを押します。

```bash
bash scripts/review-mac.sh
```

依存関係のダウンロードにはインターネット接続が必要です。Macの環境によってはネイティブSQLiteの導入で追加の開発ツールが必要です。エラーが出たら、秘密情報を除いたエラー文をこのチャットへ伝えてください。macOS上でのインストール実行そのものはまだ検証していません。

## 2. ログインする

- 初回は、確認専用のパスワードを12文字以上で設定します。入力中の文字は表示しません。パスワードをチャットへ送らないでください。
- `Ready`と表示されたら、**Mac自身のブラウザー**で次を開きます。

```text
http://127.0.0.1:3000/login
```

- メール：`review-admin@example.invalid`
- パスワード：自分で設定した確認専用のもの。
- 初回だけ、画面のキーをGoogle Authenticator等の認証アプリに登録します。時間ベース・6桁・30秒です。アプリが表示する6桁を入力します。この登録は研究会Googleアカウントとの連携ではありません。
- キー・認証コードの画像を共有しないでください。2回目以降は、同じ確認フォルダー、パスワード、認証アプリを使います。

このURLはMacの中でだけ有効です。クラウド環境のサーバーや他の人のMacには接続しません。共有用テストサイトはまだありません。

## 3. 順番に操作して確認する

| 操作 | 合格の目安 |
|---|---|
| ログイン前に参加者画面を開く | ログイン画面に戻る |
| 標準タスクを1件登録する | 一覧に表示される。対象はベーシック、名称は「架空の資料確認」、日数は検証用に-30など |
| ベーシックコースを作る | 架空の名称・会場・責任者、初回2028/3/1、次回2028/4/1を登録できる |
| 作られたタスクを見る | -30日の設定なら期限は2028/1/31になる |
| 主担当・状態・重要指定を保存 | ページを更新しても設定が残り、操作履歴に記録される |
| 日程変更案を2028/3/11にする | 期限案が表示される。ページを更新すると元の日程・期限のまま |
| イベントの申込情報を記録する | 氏名「架空の参加者」、携帯「000-0000-0000」、メール「participant@example.invalid」等を記録できる |
| 別の架空イベントに同じ氏名・携帯で記録する | 同じ参加者の履歴に2件表示される |
| 携帯の区切り等を変えて登録する | 自動紐付けされず、別の新規参加者になる |
| 代表情報の勤務先を変更する | 代表情報は変わり、以前の申込時情報と変更前の値は残る |
| 参加者を検索する | 検索でき、検索語はアドレス欄に出ない |
| ログアウトして参加者画面を再度開く | ログインが必要になる |

申込は最初「受付確認待ち」「出欠未確認」です。第4段階では次の追加確認ができます。

1. イベントの申込情報画面で定員を1人に設定し、確認チェック後に保存します。
2. 架空の申込を1件登録し、内容・照合結果を確認してチェックを入れ、「受付を確定」を押します。
3. 確定1人・残席0になり、確定者と日時が残ることを確認します。出欠は未確認のままです。
4. 別の架空申込を記録すると、満席のため確定できません。定員を2人に増やすと、締切前なら次の1人を確定できます。
5. 別のイベントを作り、過去の締切日時と未来の開催日時を設定して、残席があっても締切後は確定できないことを確認します。

満席・締切後でも情報の内部記録はできますが、席を確保したことにはなりません。定員は確定人数より少なくできません。確定取消・キャンセル・入金・キャンセル待ち・Google/LINE連携は未実装です。日程変更の保存も未対応です。

## 4. 終了・次回の起動

ターミナルで **Control+C** を押します。次回は同じフォルダーで `bash scripts/review-mac.sh` を実行します。架空データはそのフォルダーの `data/development/` に残ります。

認証アプリを紛失した場合の回復は未実装です。MFAを無効にして実運用することはできません。あくまで架空データによる検証版です。

## 確認結果の伝え方

「操作した画面」「入力した架空データ」「期待した動き」「実際の動き」をこのチャットへ伝えてください。スクリーンショットはログイン後の架空データ画面だけを共有し、パスワードやMFAキーを含めないでください。
